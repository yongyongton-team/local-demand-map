## 빈 업종은 어떻게 계산했나 (데모 기준)

1. **기대치**: 경기도 행정동 565곳(용인 제외)으로 "인구 구성(나이대, 1인 가구 비율, 평균 세대원 수) → 업종별 가게 수" 모델(포아송 회귀)을 학습하고, 용인 39개 동에 적용해 "이 동이면 보통 몇 곳"을 구해요.
2. **동 경계로 본 부족 후보**: 기대치가 3곳 이상이고, 동 안 실제 가게 수가 기대치보다 이렇게 적을 확률이 1% 이하인 경우. 용인 전체 74쌍.
3. **걸어서 갈 거리로 다시 확인**: 동 중심(그 동 가게 좌표의 중앙값)에서 반경 1km와 1.5km 안 같은 업종 가게 수를 세요(수원·성남 등 경계 밖 가게 포함). 둘 다 기대치의 절반도 안 되면 "부족". 11쌍(39개 동 중 8개 동).
4. **대형마트 확인**: 식품 업종인데 가장 가까운 대형마트가 1.5km 안이면 빈자리에서 빼요. 11쌍 중 해당 없음(구성동 과일·채소는 이마트 동백점 2.4km).

API 명세 7장에는 "반경 1km 안에 0개면 없음"으로 적혀 있어 위 기준과 달라요. 어느 기준으로 할지 팀에서 정하는 중이에요.

### `demo/data.json`의 `gaps` 읽는 법

`gaps[동 순서][업종 순서]` = `[기대치, 동 안 실제, 반경 1km 안, 반경 1.5km 안, 이보다 적을 확률, 이보다 많을 확률]`. 동 순서는 `dongs`, 업종 순서는 `cats`와 같아요. `cats[i].gain`이 0.15 미만이면 판정하지 않아요.

판정 코드는 `scripts/marts.py`의 `judge()`예요(`short` = 부족, `part` = 1.5km 안에 일부 있음, `near` = 1.5km 안에 충분, `ok` = 부족 아님, `na` = 판정 안 함).

## 다시 돌리는 법

원본(상가정보 경기 파일, 인구·세대 파일)을 `data/raw/`에 받아요. 인구·세대 파일은 CP949라 먼저 UTF-8로 바꿔요.

```bash
iconv -f cp949 -t utf-8 원본.csv > 원본_utf8.csv
```

```bash
cd data/scripts
python3 extract_stores.py <경기 상가 csv> store_counts.csv
python3 gap.py <인구_utf8.csv> <세대_utf8.csv> store_counts.csv <출력 폴더> "세탁소|반찬/식료품 소매업|약국|..."
python3 radius.py <경기 상가 csv> <출력 폴더>/yongin_gap.csv <출력 폴더>/model_summary.csv <출력 csv> 1.0
python3 marts.py ../demo/data.json <좌표 csv 출력 경로> <마트 결과 json 출력 경로>
```

- `geocode_marts.py`: 대규모 점포 주소로 좌표를 찾아요(Nominatim, 1초에 1번). 이미 찾은 결과가 `yongin/대형마트_좌표.csv`라서 다시 돌릴 필요는 없어요.
- `estimate_sql.py`: `results/yongin_dong_category_gap.csv` 전체(1,482쌍)와 동별 인구를 서버 DB 시드(`V8__seed_dong_category_estimate.sql`)로 만들어요. 창업자 리포트가 "인구 구성으로 보면 보통 몇 곳인데 동 안에는 몇 곳"을 근거로 써요. 결과 CSV가 바뀌면 다시 돌려요. 이미 배포된 V8은 고치지 말고 새 번호로 넣어요.

```bash
python3 estimate_sql.py ../results/yongin_dong_category_gap.csv \
  ../../backend/src/main/resources/db/migration/V8__seed_dong_category_estimate.sql
```
- `data.json`을 만든 스크립트는 데모 때 따로 썼고 남아 있지 않아요. 서버에 넣을 CSV는 `data.json`과 `results/`에서 다시 뽑아요.
